## 建议由维护者直接处理的部分

| 用户关心的结果 | 选择与处理 |

| 遇到断网、忙碌或取消后还能继续 | 保留进程锁等待、网络超时分类、仅清理本轮进程、事务安全停止、过期请求保护、中断副本恢复、待处理重试。取消不能撤回已完成传输。 |
| 不把密钥、代理和本机路径带到另一台电脑 | 保留本机字段投影和状态排除，完整检查未上传历史；较大首次上传分批检查，确认与推送绑定同一提交。 |

| 设置不反复丢失，普通聊天不被插件阻断 | 保留即时保存、响应丢失后的读回、有效配置展示、工具参数 schema 修复、导入身份修复及相关回归。 |
| 能看懂状态，但不增加日常负担 | 本机变化、设备回执、只读诊断、更新说明和补丁状态可按需查看；更新不自动安装。回执不代替在另一台电脑打开会话验收。 |

## 明确不纳入、以及合并时消除的重复

- **WebDAV：用户已明确排除。** P46/P47 的独立备份、连接凭据、恢复、命令、页面入口、专用测试及文档从最终候选移除；与其共用的普通冲突恢复和会话保护保留。
- **GitCode：建议本次暂缓。** P39 采用仅 GitHub。GitCode 是额外仓库后端，现有有效私有账号的实网验收不足；它不是 GitHub 正常同步的必要修复。原始源码继续归档，后续有明确需要可单独纳入。
- **旧调度：合成一套。** P24 选择 C；基准的周期双向传输、旧路线的空闲上传、后期的启动/退出不同时保留。旧间隔字段可为迁移读取，但不创建任务。
- **旧实现：保留证据，交付只留一套。** 不把 `.issue4`、`.30`、已有本地 `.20.1` 或 `work-laptop` 文件整体叠加；相同修复只实现一次，旧标签及副本先保留可恢复证据。
- **旧页面：只选一种主结构。** 首次引导、日常入口、即时保存、错误处理可组合；不同时显示四步向导、分页面导航和重复的下一步提示。
- **不新增独立转换器或加密工程。** 当前外部导入身份兼容保留，未完成的跨工具全链路、外部市场操作和已撤下的加密不冒充本次成品。

## 默认值建议

P25 不需要用户逐字段选择，整合时由维护者核对“旧文件值、宿主覆盖、最终有效值”后迁移：

- 已保存的明确暂停、启动、退出和内容范围均保持；不能把旧 `mode=manual` 不加区分地解释为用户同意开启全部自动行为。
- 对没有历史选择的新连接，建议首次先完成手动设置和预览，再按界面可见的选择启用启动/退出；这属于迁移与首次设置的小调整，不宣称已存在于旧实现。
- 演示中的开关只是示例，不读取、保存或改变用户实际配置；不会因为切换演示方案就算用户选择了某个自动开关。
