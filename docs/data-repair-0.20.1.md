# 旧数据检查、修复和离线分支

本地 0.20.1 本轮修订。先在「设置 → 同步」查看同步结果；只有会话、归属或项目文件确实异常时才需要修复。所有操作使用本机保存的原件及已知历史，不自动删除个人会话，也不自动连接其他仓库。

## 检查和修复

1. 展开同步页的「检查与修复历史数据」，点击「检查本机数据」。普通打开同步页不会扫描全部日志；若同步结果提示修复待核对，可直接点击「前往核对修复结果」，自动展开此区域并执行一次只读检查。已有修复安排时，可点击「前往处理修复安排」。
2. 找到对应的问题，先预览。日志恢复会列出可用前缀、恢复备份、已有 Git 历史；选择可靠来源后再生成写入计划。缺少可靠副本时，不补造缺失事件。
3. 核对计划后点击「确认预览，安排修复」。这时只保存计划和原件备份，尚未改写当前数据；可以取消安排。
4. 结束当前对话，完全退出所有 DSH。桌面端可在该区域点击「关闭并修复（桌面端）」；Web 端退出服务后，后台进程尝试处理已确认计划，稍候再启动。修复期间不要启动另一个 DSH。
5. 重新打开后，在左侧项目与会话列表找到修复过的会话，确认所在项目正确、没有重复或遗漏；打开会话检查最近的正文，有附件时确认能正常查看。检查无误后回到「设置 → 同步 → 检查与修复历史数据」，点击「已检查修复结果，允许同步」，再点「立即同步」。若仍有异常，先保留待确认状态，查看检查问题或预览撤销修复。未确认前启动自动同步暂停，也不发布完成回执；下次启动恢复原有自动选择。实际应用失败会保留计划、原件和错误信息；不要把“已安排”理解成“已修复”。

修复计划一天后过期。预览后文件被其他程序修改、仍有 DSH 进程、来源或备份校验不一致时停止，需重新检查。修复写入后突然退出，可从持久记录接续；已有新编辑时不覆盖。修复备份可在同一区域「预览撤销修复」，仍需完全退出后执行。

如果 Web 服务被强制结束而没有执行正常关闭流程，可在**插件安装目录或源码目录**手动运行 `node lib/data-repair-worker.mjs`，使用与原宿主相同的 `DSH_HOME`；它只处理已经确认的本机计划，不联网。先完全退出全部 DSH。此命令不创建新修复计划。

## 可以处理哪些问题

| 问题 | 处理方式 |
| --- | --- |
| 会话分错项目、跨项目重复登记、归档仍残留项目登记 | 按原会话目录预览修正；归档优先。用户有意安排的分类可取消，不强制全量重分类 |
| 项目登记缺少宿主要求的字段 | 补齐登记元数据，保留会话关系与旧原件 |
| 不完整 JSON 尾部、缺失最后换行、尾部压缩帧损坏、序号断层 | 提取最后一个完整连续前缀，或选择已有完整历史；序号不重排。尾部可能无法恢复，预览会明确提醒 |
| 项目登记表损坏 | 从已保存原件或本机已知 Git 历史预览恢复，核对宿主要求的字段 |
| 同一会话有多份当前代日志 | 明确选择保留版本，其他原件移入可恢复备份；如双方各有新增，先分别保留为会话 |
| 日志缺失 | 优先同步取回；有恢复原件时可选择恢复。没有可靠日志不能重建正文 |
| 旧配置带 UTF-8 BOM | 正常读取，保留原连接及选择 |
| 同步配置损坏 | 停止传输及自动建仓；可从此前保存的配置恢复，或备份损坏原件后重建为手动连接 |
| 原始项目目录在本机不可用 | 通过宿主接口恢复到可用的本机项目，另建独立会话并保留原始身份关系 |
| 项目目标目录同名、重叠或通过目录链接指向同一处 | 传输项目文件前停止；在检查区域展开「本机项目位置」设置不同目录再同步 |

恢复较早副本只恢复该副本拥有的内容，不代表找回损坏后全部对话。恢复之后的结果仍应由使用者打开核对。

## 两台电脑离线继续聊天

实际事件仍是同一条追加链、仅日志打包或压缩方式不同时，使用宿主的严格解码接口比较逻辑事件，原样选择完整版本，不产生重复分支。

如果两边确实各自继续了不同对话，原会话继续保留，双方原件另存。打开相应原件预览，可看到共同历史和两端独有的事件数量。选择本机项目，点击「保留两端会话并继续」；插件只为当前会话尚未包含的分支建立独立会话，保留来源关系，核对附件与读回，重复点击接续同一记录。

两条独立对话中可能存在同序号工具调用、文件操作与轮次关系，不能直接拼接日志。独立分支可以分别继续，必要时将另一分支的结论作为普通聊天信息带入当前对话；插件不会把模型生成的总结冒充原始历史。

## 重新打开提示和容量边界

仅存在明确待应用更改或已确认修复时显示非模态提示；同步中、对话活跃时不弹出，单纯未分组数量变化不会反复触发。「稍后」对同类提醒抑制 12 小时；自动分组重启也设有 12 小时去重。手动入口始终可用。重新打开后清除上一宿主已应用的刷新需求，仍有待写入内容则保留提示。

关窗到托盘仍不是退出。取消不撤销已完成传输。强退、立即关机、另一宿主占用或断网仍可能使退出处理未完成，下次启动应查看实际结果。

会话检查、传输与恢复按同一 256 MiB 日志上限处理；压缩日志以解压后的大小核对，单个大日志独立批次扫描，仍检查尾部敏感内容。普通文件保持 8 MiB 单文件扫描保护；超过边界会明确停止，不跳过安全检查。恢复种子有额外 1 MiB 元数据余量，不是无限容量承诺。

回执只在所选内容已实际应用、没有待确认、待修复、分叉或待写入内容时发布。旧回执缺少新版应用验证标记时，不作为另一端已完成的证据；回执仍不能代替打开正文和附件验证。
