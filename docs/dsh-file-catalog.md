# 冲突原件中的文件是什么

先看聊天、项目分组、设置和插件是否正常。同步保留了双方原件，不代表每条记录都需要你选一个版本。原件页显示当时的处理结果；合并未完成时先检查同步错误。

| 路径 | 对使用者的含义 | 什么时候需要处理 |
| --- | --- | --- |
| `storages/sync-meta/**.vmap.json` | ChatSync 自己的修改先后账本，帮助两台电脑合并设置；不是聊天内容，也不是关联文件本身 | 正常时无需选择或手工编辑 |
| `profiles/<环境>/package.json` | 插件清单：想安装哪些插件、版本要求、启动装入哪些功能 | 插件缺失或异常时通过插件管理检查；同步清单不等于安装完成 |
| `profiles/<环境>/pnpm-lock.yaml` | 安装工具记录的最终依赖版本、来源及校验信息 | 通常无需处理；让安装工具配合清单更新，避免单独恢复 |
| `profiles/<环境>/pnpm-workspace.yaml` | 安装规则，可能涉及依赖覆盖、安装脚本许可等 | 安装报错时结合错误检查；不是聊天项目列表 |
| `profiles/<环境>/cordis.patch.yml` | 启动时应用的功能及设置配置补丁 | 设置或插件不符合预期时通过对应界面调整 |
| `settings.yaml`、`settings.yaml.imported` | 旧版设置及迁移原件；不保证是当前生效配置 | 先核对设置页，不直接覆盖 |
| `storages/workspace.json` | 项目分组、会话归属相关登记数据 | 分组异常时保留原件排查，不手工拼接 |
| `sessions/**` | 会话原始记录 | 确有消息遗漏时，比较可读原件，按支持情况建立独立会话 |
| `attachments/**` | 聊天附件 | 无法打开或内容不对时核对原件；二进制不做文本差异 |
| 项目文件夹中的文件 | 由项目定义用途，同名 `package.json` 也不是 DSH 系统配置 | 确有遗漏或错误时再决定恢复，恢复前备份 |

`web` 指网页版，`desktop` 指桌面版；其他名称指对应运行环境。未知路径保留“用途尚未确认”，不会凭文件名套用系统文件解释。

## 逐版本核对的范围与证据

2026-10-21 从官方 npm 注册表枚举 `@deepseek-ai/dsh` 的全部 36 个已发布版本（`0.0.1-rc.1` 至 `0.2.1-rc.2`，含预发布版本）。读取同版本的 DSH、启动器、设置、工作区、插件管理、JSON 存储和会话日志持久化包，共 230 个发布包。仅下载和解析，未安装或运行下载代码；按注册表 integrity 校验，记录包和源码文件 SHA-256、命中位置及原文片段。

这是一份**相关文件的发布源码核对**，不是对 36 个版本逐个启动安装验收，也不是 DSH 所有数据文件的完整格式规范。自动识别结果只是说明依据，不用于改变同步策略、裁决文件或覆盖数据。早期包未能从这组源码确认的设置路径标为 `unconfirmed`，不推断为“没有设置文件”。

本机桌面端实际为 `0.2.1-rc.2`，另读取其安装内的官方包交叉核对。本机的 `dsh-settings/lib/index.js` 明确执行：把 `settings.yaml` 改名为 `.imported`，再导入当前 profile 配置。因此旧设置原件不能直接代表现在生效的设置。在本次核对范围中，`0.1.7-alpha.1` 起的设置包存在该迁移入口；更早版本保留未确认标记。

历史恢复记录没有保存创建时的宿主版本，也没有另一台电脑的 DSH 版本。界面明确显示“按本机当前版本解释”的边界。未列入目录的后续版本或无法识别的宿主显示尚未核对，不静默沿用已确认标记。

证据归档：`outputs/conflict-experience-20261021/catalog/official-catalog.json`（逐包来源、integrity、文件清单及源码定位）、同目录的原始 tarball、`official-source-evidence.json`（本机官方包）。随安装包的精简逐版本目录为 `lib/dsh-file-catalog.json`。重新采集可在维护源码运行 `node scripts/check-dsh-file-catalog.mjs`，默认保存到本次输出目录，不访问个人同步仓库。

官方参考：[DSH 启动器的 profile 说明](https://www.npmjs.com/package/@deepseek-ai/dsh-app-boot)、[pnpm 锁定文件说明](https://pnpm.io/lockfile)。实际解释以固定版本发布包为准，不用官网最新说明推断历史版本。

## 对比与恢复边界

“预览双方原件”直接打开独立大窗口，可关闭或按 Esc 返回。左右按相同行高对齐，插入与删除以空白行补齐；红色 `−` 和绿色 `＋` 标出差异，滚动位置同步，并提供上一处、下一处差异。关闭只收起预览，不删除记录或改变同步结果。

预览保持只读。项目文件恢复、独立会话导入继续要求确认，沿用原件校验和恢复前备份。二进制或无法解码的内容不生成文本差异。服务器预览最多读取部分内容；大文本超过计算上限时只按行展示、最多 3000 行，明确提示截断和未计算差异，不能据此判断完整文件相同。
