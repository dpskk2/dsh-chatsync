# 分组检查与归档行为 · 2026-10-23

本机修订为 0.20.1 / 2026-10-23-grouping-intent，未发布 npm / GitHub。

## 用户可感知变化

- 设置按同一左侧基线排布，去掉多余的「同步设置」套层和重复内缩；内容选项仍以边框区分。规则链接、项目位置和自动同步之间有独立留白。
- 删除工作区只删除工作区登记，插件不再按残留会话的 cwd 补建工作区。正常未分组和未分组中的归档会话单独显示，均不触发修复。
- 分组异常依据为：已登记到现有项目但宿主未显示，或在本轮同步应用登记表前后观察到归属丢失且原工作区仍存在。后者保存本机证据，登记表之后发生用户修改即不再沿用旧证据。数量多、目录名相同或没有归属，都不能单独证明同步损坏。
- 项目合并以共同基线识别删除，避免旧远端工作区、已移除归属或已取消的归档重新出现。无共同基线时不能猜测历史删除。
- 归档是全局显示状态，保留工作区的会话位置。插件不再清除归档会话的有效项目登记。

## 检查时机

设置和同步状态查询会读取本地分组情况；前端提醒每 5 秒查询并连续确认，后台每 15 秒检查稳定的宿主分组刷新问题。这些检查不发起网络同步。同步应用项目登记表时会记录前后变化，手动进入处理页另做完整数据检查。未分组提示开关控制提示及按需刷新，不自动补建已删除工作区；检查页始终可手动进入。

## 当前官方 DSH 的行为依据

检查当前安装包中的 @deepseek-ai/dsh-workspace 0.2.1-rc.2 和 dsh-client-ui-workspace 源码，并用同一安装包的 Desktop Host 做隔离验证。工作区 delete 保留会话日志与目录；归档仅改变 archivedSessionIds，保留 sessionIds 槽位；取消归档仅改变归档状态。侧栏「未分组」是没有工作区归属的会话分组，不是自动新建的真实工作区。归档筛选开启时，没有归属的归档会话也会出现在这里；有归属的归档会话留在原工作区。

## 验证

专项覆盖删除工作区后多次同步钩子不补建、归档仍保留项目位置、同步前后证据失效、三方删除合并，以及本机删除记录阻止旧远端日志与归档登记重新导入。真实隔离 Desktop Host 验证归档、取消归档、删除工作区、检查结果与重启后的正常未分组状态。个人数据清理及每日 Desktop 安装、目视验收记录在 outputs/grouping-intent-20261023/；不代表物理双机验收。
