# 0.21.2 验证范围

发布日期：2026-11-06。构建：2026-11-06-release-0.21.2。逐项结果、命令、环境与哈希见 [发布证据](https://github.com/dpskk2/dsh-chatsync/blob/v0.21.2/release-evidence/0.21.2/manifest.json)。

本版改动：macOS 桌面端的退出上传、更新命令、系统代理和 Git 登录（[#17](https://github.com/dpskk2/dsh-chatsync/issues/17)）；第二台电脑接入后的项目分组（[#21](https://github.com/dpskk2/dsh-chatsync/issues/21)）；Windows 与 macOS 共用同步仓库（[#17](https://github.com/dpskk2/dsh-chatsync/issues/17)、[#10](https://github.com/dpskk2/dsh-chatsync/issues/10)）；慢速网络下首次上传不再被中断、Git 错误按类别说明、同步页的网络连接检测、疑似密钥改为提醒、GitHub 单文件上限、同步副本本机历史截短、编号不带前缀的会话（[#13](https://github.com/dpskk2/dsh-chatsync/issues/13)）。

## 必过项（补丁版）

- **完整回归。** 冻结后的发布源码在 Windows 11 上分别用独立 Node.js 24 和 DSH Desktop 内置的 Electron / Node.js 运行完整测试，要求 0 失败、0 取消、0 跳过（Windows 图形界面用例由桌面端内置运行时执行）。
- **候选包隔离宿主检查。** 把实际发布的安装包（含短包名 `chatsync`）装入隔离的桌面宿主（DSH 0.2.2-rc.1），核对加载的文件哈希、版本与构建，通过公开接口读写并冷启动后读回；不使用维护者的日常数据。

## 与本版改动相关的检查

- **macOS 自动测试。** CI 新增 macOS 任务，在 GitHub 托管的 macOS 环境上运行完整测试、代码检查和安装包内容检查。按进程参数识别宿主、更新命令、`scutil --proxy` 解析、`osxkeychain` 凭据设置、`.DS_Store` 排除和 Windows 不允许的文件名都有对应用例；只属于 Windows 的 7 个用例在 macOS 上跳过。
- **DSH 0.2.2-rc.1 格式核对。** 对照 0.2.1-rc.3 至 0.2.2-rc.1 的标签源码和官方会话格式包：会话仍是 V4，事件类型不变；项目登记和设置文件的位置、结构不变；新增的设置只有两个可选的服务商字段。旧版宿主拒绝 0.2.2 的分叉会话时，同步按原规则停止并提示更新。详见 [DSH 文件核对](dsh-file-catalog.md)。
- **项目分组（#21）。** 自动测试覆盖第二台电脑首次接入、每台电脑保留自己的项目路径、接入后的删除仍然生效。一台电脑上的两个隔离桌面宿主（DSH 0.2.2-rc.1，本地裸仓库和合成数据）确认：重启后两边的项目和 3 个会话的分组都保留。
- **跨系统同步（#17、#10）。** 自动测试用本地裸仓库模拟 Windows 和 macOS 设备，确认 Windows 会话不中止 macOS 上的同步、保留在远端、分组、归档和置顶不丢失，项目路径按主目录对应。
- **传输超时。** 自动测试用持续输出进度的子进程确认：超过无进度时限的传输不会被结束；停止输出进度后在时限内被结束，并记录停滞时长；没有进度回调的命令仍按总时长结束。
- **错误分类。** 自动测试覆盖网络中断、代理、HTTP 413、GitHub 大文件拒收、远端已有新内容、登录与权限、仓库不存在、受保护分支、磁盘已满、未安装 Git 和未知错误；Git 原文去掉进度行并隐藏凭据。
- **网络连接检测。** 自动测试覆盖 Git 自身代理、插件代理、环境变量、系统代理的优先顺序与凭据隐藏；直连 GitHub 时生成只对 GitHub 生效的设置与撤销命令；国内托管站与 SSH 地址不给命令；连通失败时给出分类原因。
- **本机历史截短。** 用本地裸仓库验证：与远端一致时截短到指定次数，远端仍保留全部历史；本机有未上传的提交或只在 reflog 中的提交时不截短；共同起点落在截掉的部分时，先补回完整历史再判断。
- **疑似密钥与文件大小。** 自动测试确认疑似密钥与敏感文件名只作提醒、照常上传；超过读取上限的内容照常上传；GitHub 远端下新加入的超过 100 MB 的项目文件留在本机、其余文件照常提交，已同步的文件和会话日志不跳过。
- **编号不带前缀的会话。** 端到端测试：另一台电脑推送的不带前缀会话经宿主写入接口正常写入；序号不连续的同类会话被拒绝。这三项在旧规则下失败、新规则下通过。

## 验证边界

- **没有真机 macOS 验收。** CI 的 macOS 任务只运行自动测试，不启动桌面端。退出时上传、退出后执行修复、系统代理、钥匙串登录和更新命令都没有在真实 Mac 桌面端试过。
- 没有物理双机证据。#21 没有经过物理双机加 GitHub 实网往返，也没有在报告者的实际环境中验证；分组修复后的自动重启只由自动测试覆盖。
- Windows 与 macOS 共用同步仓库只用本地裸仓库和模拟设备验证，没有两种系统之间的真实往返。
- 0.2.1-rc.5 宿主只核对了标签源码，没有实际运行。
- 慢速网络与代理检测只用本机子进程和替身验证，没有在真实的低速网络或真实代理软件上实测。
- GitHub 100 MB 上限只验证了项目文件路径和导出时的筛选逻辑，没有向真实 GitHub 推送超限文件；Gitee、GitLab 的单文件上限未知，没有预设。
- 编号不带前缀的会话只用合成数据和测试用宿主写入接口验证，没有在真实 DSH 宿主中用这类会话做往返。
- 完整故障注入矩阵与恢复演练未在本版执行。
