# 0.20.1 启动同步体验修订

2026-10-21 在唯一维护目录修订，沿用尚未对外发布的 0.20.1。本轮不发布 npm / GitHub，不改写旧标签或旧交付证据；本次安装包和验证记录另存于 `outputs/startup-experience-20261021/`。

## 本次启动为什么等待

部署记录显示首次建立独立同步副本，接收 6636 个 Git 对象、182630482 字节（约 174 MiB）；Web 同时启动时等待桌面端释放同步占用。完成后并没有继续传输，而是等待用户确认包含插件安装清单的变化。旧页面在这些状态中都突出“启动同步”，使等待原因和下一步不明确。

独立副本按仓库和分支复用，不按插件版本重建。本次保留已建立的副本，不清缓存、不删除会话。后续首次建立副本时，如果本机已有 Git 历史，优先借助这些对象减少重复传输；随后解除依赖并保存独立对象，不以本机未上传提交作为远端初始版本。

## 页面变化

- 运行中突出当前任务。下载和上传显示当前步骤的百分比、数据对象数量、字节数及速度；百分比来源是 Git 对象传输进度，不冒充整轮进度或预计剩余时间。
- 连接、核对、排队等无法计算百分比的阶段显示活动进度条与说明；等待另一端时明确说明两端共用数据。20 秒无新进度回报时提示可先离线进入，不自动绕过确认。
- 当前传输结束、进入下一阶段时清除旧传输条，避免继续显示上一阶段的 100%。修复一批 Git 回车更新只显示较早百分比及跨数据块断行的问题。
- 确认时停止进度与计时展示，标题明确“请确认这次同步”；先显示数量与影响，再显示确认上传 / 取回按钮。具体文件路径和确认说明折叠查看。
- 启动弹窗每秒读取轻量状态快照，不再为画进度重复调用全量会话状态扫描；请求不重叠，连接超时显示重连提示。

## 验证记录

验证结果及实际部署证据见维护目录 `outputs/startup-experience-20261021/`。真实前端页面检查使用生产 `lib/client.js` 与 React DOM，但 HTTP 数据为隔离夹具；截图不是个人 DSH 的传输结果。现有确认、取消、离线和原件保护继续适用，不会自动批准上传或取回。网络、仓库体积、工作区数量和另一端占用仍可能影响实际启动时间。

本次完整隔离回归 243 项全部通过，无失败或跳过，补丁检查 8 项断言通过；真实前端通过明暗主题与 390 / 1150 像素宽度的下载、核对、排队、确认和离线交互检查。实际 Web 宿主上以 0.20.0 引擎与当前源码完成第 0–4 代日志升级、双副本往返与重启读回；均使用合成数据和本地 Git。首次副本复用检查确认旧仓库对象暂时不可用时新副本仍可完整读取，本机未上传提交未被用作远端初始版本。
