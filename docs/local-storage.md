# 本机存储（实验性）

chatsync 负责各电脑之间当前用户数据的同步。同步过程为防止覆盖丢失而保留的原件，不是全量备份服务。新增文件和成功的会话追加不再产生整份恢复副本；实际覆盖、分叉或应用失败时仍保留必要的原件。

在「同步仓库与本机存储 → 本机存储 → 明细」中，分别显示：

| 类型 | 是什么 | 是否同步 |
| --- | --- | --- |
| 当前同步副本 | 隔离的当前文件树，以及主数据和项目安全合并所需的 Git 数据 | 仅传输所选的当前内容与合并增量；不上传整个目录 |
| 恢复与冲突原件 | 覆盖前保留的版本、真正分叉的会话和待处理种子 | 否 |
| 旧同步仓库 | 旧版主 Git 仓库、失效副本和已不再使用的项目仓库 | 否 |
| 旧版隐私处理副本 | 旧版本隐私处理留在本机的原件副本 | 否 |
| 运行与处理记录 | 同步状态、处理依赖和记录 | 否 |

首次同步只取远端当前快照；不会为统计仓库占用而下载完整旧历史。清除同步分支历史时，旧历史留在 GitHub 的归档分支，不再生成完整的本机 Git bundle。已有的旧 bundle 仍能在此查看与清理。GitHub 归档仍占用远端空间，但不参与新电脑默认同步。

默认保留最近 30 天，可选 7、90、180、365 天或不按时间保留。删除只在选择、预览并确认后进行。当前同步副本、未完成或被引用的恢复原件、活动种子、在用项目 Git 库始终受保护。

旧主 Git 仓库在确认已建立当前同步副本、原仓库地址相同、没有未提交改动，且全部提交（包括分支、标签和 reflog 中的历史）已被当前副本覆盖后，才可以选择清理。其他旧同步副本中的未上传内容、暂存和 reflog 独有历史同样受到保护。旧版隐私处理副本也可以按项选择。确认页必须额外勾选不再需要所选旧材料；删除前会重新检查全部材料与依赖，变化即停止。

会话迁移已由宿主读回校验、新会话归属确认且旧会话完成归档后，预览索引不再阻止该次迁移原件的清理；仍需满足保留时间，并由用户选择、预览和确认。未完成导入或仍被其他处理引用的材料继续保留。以后再次处理旧会话时，按当前原件重新建立恢复记录。

检查范围只包括本插件产生的存储，不把 DSH 的 Electron、运行时、插件安装目录、手工 backup/、patches/ 等其他材料计作本机备份。显示大小为文件逻辑大小；硬链接共用的内容实际占用更小。
