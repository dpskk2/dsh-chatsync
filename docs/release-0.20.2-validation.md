# 0.20.2 验证与升级说明 · 2026-10-24

本版落实 issue #4、#6 及后续审查发现的同步缺陷。自动测试使用隔离数据和真实本地 Git；同一机器的两个目录不等于两台物理电脑。

## 修复范围

| 用户关注点 | 本版行为与检查 |
| --- | --- |
| 首次项目同步失败、不同 Windows 用户名 | 空远端、尚无项目分支与网络探测失败分别处理；项目和主数据使用一致的凭据策略，空 Git 身份采用本地默认值；错误保留可读原因并隐藏凭据。 |
| 大文件导致反复失败 | 上传前按对象检查上限，先停止并提示具体文件；取消被拒绝的暂存，允许添加忽略规则后重试；不删除原件、不改写旧远端历史。已陷入旧历史大文件阻塞时，可预览并确认：保留本机旧提交备份，用同一文件快照重新建立待上传历史，再正常同步。 |
| 编辑器保存与项目合并交错 | Git 在隔离目录合并；应用前再次核对项目文件，遇到新修改保留本机文件并提示重试。替换前保存备份并移动保留原始文件，目标新建时不覆盖。 |
| 取消或中断项目合并 | 清理隔离目录的未完成合并；禁止提交未解决冲突。应用中断后先恢复或保留原件，再允许重试。 |
| 会话序号连续但语义损坏 | 传输前调用宿主公开格式校验器检查语义与身份；取回时在合并前检查，离线应用同样检查。旧格式按官方历史词汇校验并保留原字节，不虚构迁移所需的子会话证据。 |
| 设置注释、转义引号、URL 列表 | 使用附带 MIT 许可的 js-yaml 4.1.1；阻断重复键、危险结构和超限输入。保留设置值的含义，格式和注释可能规范化。 |
| 损坏登记表、本机路径文件 | 明确停止，避免静默空列表或错误目录；支持带 BOM 的正常 JSON。 |
| 退出上传与换机回执 | 存在尚未应用到本机的远端内容时显示待取回，不写成“已应用”的回执。正常退出上传仍不等于托盘、关机或强退保证。 |
| 中文、空格等项目文件名 | Git 路径列表采用 NUL 分隔，冲突原件可正常识别和保留。 |
| 代理与中文错误输出 | Git、gh 继承已有代理环境，显式代理优先；完整拼接字节后解码，避免分块打断中文。系统代理仍需由宿主或环境配置提供。 |
| 自动同步关闭后重启又开启 | 同步页明确保存的现代开关选择优先于宿主默认值；保留旧配置迁移规则。 |
| 删除模型提供方、保留本机密钥 | 被删除的提供方不再阻止无关设置更新，也不会把其密钥附加到另一提供方；应用前的完整设置保留在本地备份。 |

## 升级和恢复

- 更新插件后重新打开 DSH，并核对版本 **0.20.2**、构建 **2026-10-24-release-0.20.2**。本版不修改 README，也不自动更新用户的日常安装。
- 原有 Git 历史和本机数据保留。旧历史中的超限文件不会被自动清理；仍然受阻时，请先根据提示排除当前快照中的大文件并重新同步。在问题详情中点击「处理项目旧历史中的大文件」，核对说明后点击「保留备份并重建待上传历史」，最后再次同步。该步骤保留旧提交为本机备份，不改项目文件、不强制推送；预览过期或远端已变化会要求重新核对。不要以删除会话、备份或强制推送作为通用排障步骤。
- 项目应用备份除 DSH 的本地恢复记录外，还保留在项目目录旁的 `<项目目录>.chatsync-backups` 中，便于在不同盘符保持同一文件系统。此目录属于本机恢复数据，不进入同步；不要在尚未核对前删除。`latest-original` 保留替换前的文件，打开旧文件句柄的编辑器可能继续写入它。
- 提示“上次项目应用中断”时先核对项目和恢复记录，再重试；提示备份目录被占用时应检查该目录，不要直接删除已有文件。被移动的原件和待应用内容都保留。
- 会话语义校验依赖宿主公开的格式包。接口缺失、版本未知或输入不能校验时停止并保留原件，不能把“未上传”当作同步成功。

旧版迁移到隔离项目目录时，以旧快照核对本机删除，避免把已经删除的文件重新带回项目。

## 证据和边界

源码、自动回归、故障回归与安装包检查见 `release-evidence/0.20.2/`。测试使用官方发布的 0.2.0-rc.2 会话格式包作为独立判定来源；原有引擎行为测试中的有限模拟不代替官方格式校验。
