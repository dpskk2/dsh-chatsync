# 0.21.3 验证范围

状态：发布候选，尚未定版。构建：2026-11-08-release-0.21.3。逐项结果、命令、环境与哈希见 [发布证据](https://github.com/dpskk2/dsh-chatsync/blob/v0.21.3/release-evidence/0.21.3/manifest.json)。本文件只记录已经实际完成的检查；尚未完成的必过项列在「验证边界」中，完成后再更新。

本版改动：设置版本记录卡死后的修复与「清除版本记录」；登录帮助按仓库类型分为三个子标签并加入 GitHub 授权示意图；自建 SSH 服务器作为同步仓库（实验性，[#25](https://github.com/dpskk2/dsh-chatsync/issues/25)）。

## 必过项（补丁版）

- **完整回归：未完成。** 要求冻结后的发布源码在 Windows 11 上分别用独立 Node.js 24 和 DSH Desktop 内置的 Electron / Node.js 运行完整测试，0 失败、0 取消、0 跳过。目前只在 Linux 上用独立 Node.js 24 运行过完整测试（见下文），不能代替 Windows 与桌面端内置运行时的回归。
- **候选包隔离宿主检查：未完成。** 实际安装包（含短包名 `chatsync`）尚未装入隔离的桌面宿主核对。

## 与本版改动相关的检查

- **设置版本记录（B1）。** 自动测试按维护者报告的场景复现：两台电脑都用 0.2.1-rc.5 同步后都升级到 0.2.2-rc.1，修复前三轮同步都提示「两台电脑的 DSH 版本不同」、远端记录不变；修复后第一轮即恢复设置同步，远端记录改为 0.2.2-rc.1。另外覆盖：较新的一台接管后仍是旧版的电脑暂停，不取回、不覆盖远端设置，附件照常同步；无法比较的版本（如 `dev-build`）与记录不同时仍暂停；原有「旧版暂停、升级后恢复」和「无法检测版本按原方式同步」两条测试保持通过。版本比较的单元测试覆盖预发布低于正式版、`rc.10` 高于 `rc.9` 和无法解析返回空。
- **清除版本记录（B2）。** 自动测试用本地裸仓库与合成设置确认：清除后恢复记录数量等于同步仓库中的设置文件数，本机与远端两侧字节与清除前一致；清除本身不改动同步仓库；下一轮同步不暂停、远端记录改为本机版本、本机标记删除，再下一轮不再报告清除结果。页面过期（记录版本不符）、同步进行中、无法检测本机 DSH 版本时拒绝且不留恢复记录和标记；备份写入失败时不写标记，下一轮仍暂停；标记针对的版本被第三个版本取代时仍暂停并删除标记。新接口拒绝跨站、非 JSON 和超大请求体。界面测试确认只有暂停结果带版本信息时显示按钮，取消确认不发请求，确认后先清除再开始同步。
- **登录帮助（A）。** 界面测试覆盖：未连接仓库时默认「GitHub 仓库」，已连接 GitHub / Gitee / 自建服务器时分别打开对应子标签；一次只渲染一个面板；点击和左右方向键切换，`aria-selected`、`tabIndex` 随之变化；各子标签的命令与链接；示意图 8 个编号只在 GitHub 页出现。示意图中的英文输出按 GitHub CLI 源码核对（`! One-time code (…) copied to clipboard`、`Press Enter to open … in your browser...`、`✓ Authentication complete.`、`✓ Logged in as …`），用 GitHub CLI 2.89.0 实际运行确认了第一个提示 `? Authenticate Git with your GitHub credentials? (Y/n)`；后续步骤因测试环境的网络限制无法取得一次性代码，没有实际走通。用插件样式表在 390 px 宽、浅色和深色下渲染三个子标签，均无横向滚动。
- **自建 SSH 服务器（C）。** 地址解析测试覆盖支持的三种形式，以及 HTTPS、`git://`、`~` 路径、含密码、`..` / `.` 路径、非法端口和托管站地址被拒绝；普通「使用其他仓库」输入仍拒绝绝对路径与单级路径。私有检查测试确认只有在自建服务器子标签保存的确切地址跳过匿名读取，地址改变后恢复原检查。端到端测试用 Git 的地址替换把一个 SSH 地址指向本地空裸仓库，两台模拟设备从子标签保存地址、首次上传到空仓库并取回，全程没有匿名读取；自建标记不出现在同步仓库中，改存普通地址后标记清除。保存失败时按指纹未确认、密钥被拒、仓库不存在、连接失败给出原因且不改配置。
- **完整自动测试（Linux）。** 见发布证据中的 `data-loss/automated` 记录。

## 验证边界

- Windows 上独立 Node.js 与桌面端内置运行时的完整回归、实际安装包的隔离宿主检查尚未完成，须由维护者在 Windows 本机完成后才能定版。
- 自建 SSH 服务器没有在真实 SSH 服务器上验证：主机指纹确认、密钥登录、非默认端口和 `ssh-agent` 只按 Git 与 OpenSSH 的报错文字编写了提示，没有实测。
- 「清除版本记录」与 B1 的版本接管没有物理双机证据，也没有在真实 DSH 宿主之间实际升级 / 回退 DSH 版本验证。
- 登录帮助只在合成页面中按插件样式表渲染检查，没有在 DSH 桌面端窗口中目视验收；GitHub 授权的浏览器步骤没有实际走通。
- 取回远端后才发现记录变得比本机新的情况：本机在推送前已经按旧记录判定，若另一台更新版本的电脑恰好在本机取回与推送之间写入，本机的设置仍可能随本轮推送；这一窄窗口与 0.21.2 相同，本版未改变，也没有专门测试。
- 完整故障注入矩阵与恢复演练未在本版执行。
