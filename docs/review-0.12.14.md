## 已实现的功能与边界

| 功能 | 当前实现 | 边界 |
| --- | --- | --- |
| 连接仓库 | 设置页保存 HTTPS / SSH 地址、分支与自动建仓选项；写入前核验私有仓库 | 保存连接不等于登录与传输成功；不是只下载模式 |
| 同步方式 | 手动 / 自动、总开关、周期可编辑，保存后刷新调度器 | 启动和活动触发为双向同步；正常退出只尝试保存与上传，不保证强制退出时执行 |
| 会话与配置 | 会话严格追加时原样保留完整历史；配置与登记表按字段处理 | 会话分叉保留一侧并报告双方提交，不能保证两边新增都出现在当前会话 |
| 工作区文件 | 影子 Git 仓库和独立分支、跨机路径映射、本机路径覆盖 | 开关关闭后上传与取回均暂停；凭据识别不覆盖项目所有文件 |
| 分组与重启 | 分组修复、空白会话过滤、活动检测、引导浮层、Web / 桌面重启 | 磁盘与宿主内存仍依赖重启对齐；未知活动允许自动重启 |
| 排障 | 进度、上次结果、备份上传状态、会话分叉原件位置、遗留副本预览 | 不提供图形化选择性恢复；遗留副本不是当前冲突待办 |

## 修改建议（按优先级）

### P1：自动重启应等待整个同步完成

依据：`lib/sync.js` 的 `_syncOnce()` 在主数据修复后调用 `scheduleRestartAfterRepair()`，随后才等待 `syncAllWorkspaces()`；桌面重启脚本只等待固定 2 秒。

触发：开启自动重启，本次取回新会话或补登记，同时还需要传输较大的工作区文件。重启任务可能在工作区传输中关闭宿主，导致传输中断或响应未返回。此项为控制流确认的风险，未执行破坏性的真实重启复现。

建议：本轮仅记录需要重启；在全部工作区传输完成、结果保存、进程锁释放后再调度。发生任何同步失败时保留手动提示。验收应模拟慢传输，断言工作区完成前没有调用重启调度。

### P1：活动检测必须区分未知和空闲

依据：`lib/session-activity.js` 的 `sessionDirs()` 吞掉目录读取错误并返回空数组，`probeLogActivity()` 将数组结果标为 `available: true`；`restartGuardState()` 也明确放行未知结果。

本轮只读复现：无 agents 服务并传入不存在的 home，结果为 `available:true, activeCount:0, source:"log-activity"`。不可读目录不能证明没有会话在生成；仅按日志 mtime 判断也可能漏掉长时间等待工具的会话。

建议：返回“已确认空闲 / 活跃 / 未知”三种状态；枚举或日志读取失败为未知，自动重启只接受已确认空闲。手动重启继续允许用户确认，界面按来源显示“正在生成”或“近期活动”，避免把推测说成事实。

### P1：重启接口应检查同步中状态，并显式接收强制确认

依据：`lib/index.js` 的 `/api/restart` 无条件传入 `force: true`，未检查 `engine.inFlight` / `progress.running`。前端禁用按钮只覆盖当时的界面状态，后台同步仍可能在确认框出现后启动；接口的活跃会话 409 分支因此也无法用于当前请求路径。

建议：服务端同步中返回 409；默认请求执行活动守卫，只有请求中明确确认才允许强制重启，并在执行时重新检查状态。验收覆盖“确认框出现后开始自动同步”和“接口直接调用”两种情况。未在真实宿主发送重启请求。

### P2：设置保存反馈应始终使用实际生效值

依据：`SyncPreferences.save()` 的覆盖检查只比较 `mode` 和 `workspaceSync`，遗漏 `enabled`、`intervalSeconds`；`toggleAutoRestart()` 直接用所选值显示成功，忽略返回的有效配置，也没有保存中的禁用状态。

影响：宿主覆盖参数时，表单可能恢复旧值但仍提示所选值已生效；快速连续点击重启开关可能导致显示与最终保存结果不同。

建议：统一比较提交字段与返回配置；开关也以返回值更新，保存中禁用并展示错误。保留现有的未保存连接草稿保护。

### P2：遗留副本加载失败不应无限显示“正在读取”

依据：`Section.loadConflicts()` 的异常被忽略，失败后 `conflicts` 仍为 `null`；返回 `ok:false` 时还可能被解释成空列表。

建议：校验 `ok`，分开显示加载、空列表、失败状态，提供重试。高级区域可默认折叠，减少设置页占用。

### P2：首次传输应让用户看见范围，恢复应有独立入口

当前工作区默认开启，依赖忽略规则；界面没有待传输目录、文件数、体积和排除项预览。双方文件冲突与会话分叉虽保留 Git 原件，但普通用户仍需手工查 Git 历史。

建议：先增加只读传输范围预览与凭据排除说明，再增加指定文件的历史预览、导出和选择性恢复。恢复前保留当前副本，避免通过全目录 reset 完成常规操作。此项是产品改进建议，不是已复现的数据丢失。

## 本轮文案处理

- 连接、同步方式、工作区选项采用短说明；触发时机、排除项与冲突规则移至折叠说明。
- 修正“开机只拉取”“关闭工作区仅停止上传”“会话按事件拼接”“未分组已经全部修好”等容易误解的表述。
- 同步按钮提示按已保存设置执行，避免关掉工作区同步后仍声称会传输所有工作区。
- 继续保留私有仓库、敏感文件、活动未知时自动重启等必要边界。
