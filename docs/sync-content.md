# 同步内容

| 类别 | 包含 | 关闭时 |
| --- | --- | --- |
| 会话 | 会话日志、项目归属和相关登记信息 | 暂停上传与取回，保留远端已有内容和本机原件。 |
| 聊天附件 | 对话中上传的图片、文件 | 暂停该类两个方向的传输。 |
| 可共享设置 | 主题、字体字号、模型、搜索与插件偏好 | 各机密钥、代理与路径始终保留；关闭后不交换设置。 |
| 指令与技能 | 数据目录下的全局 `AGENTS.md` 和 `skills/` 文件夹（DSH 每次对话都会读取） | 默认关闭，每台电脑各自选择；关闭时不上传也不取回。 |
| 项目文件 | 项目目录的代码、文档，包括生成在项目目录中的 Word / Excel | 独立开关，关闭后同时停止上传与取回。 |

设置补丁（`cordis.patch.yml`）两边都改过时按插件条目合并：不同条目各自生效，同一条目两边都改过则保留本机，另一边留在恢复记录中。补丁列表含插入项或重复条目时，执行顺序有意义，仍整份保留本机。

两台电脑的 DSH 版本不同时，设置暂停同步：新版 DSH 可能改写设置格式，旧版既不会收到，也不会覆盖它。同步状态会提示两台的版本；把 DSH 更新到同一版本后自动恢复，会话和附件照常同步。无法确定版本时按原方式同步。

数据目录中只同步上表列出的内容。「可共享设置」具体是 `settings.yaml`、数据目录和各环境的 `cordis.patch.yml`、同步偏好和忽略规则。插件安装清单与锁定文件（`profiles/<环境>/package.json`、`pnpm-lock.yaml`、`pnpm-workspace.yaml`）、各种工具留下的备份、脚本、令牌以及其他插件或手动放入数据目录的文件，都属于这台电脑，不会同步；以后 DSH 新增的文件也要经确认列入后才同步。旧版本已经上传的这类文件留在远端，不再取回或覆盖。所有在用的电脑都升级后，可在同步页「同步仓库与本机存储 → 远端旧文件」把它们从同步仓库最新版本移除，各电脑上的这些文件留在原处。窗口里会列出仍是旧版本、版本未知或超过 30 天未同步的电脑，以及各自的最后同步时间；旧版本会把远端移除当作删除本机文件，所以要先在这些电脑上升级并同步一次，不再使用的电脑可以勾选跳过。

项目文件沿用本机路径映射，不能指向 DSH 数据目录或与之互相包含。默认排除 Git 元数据、`node_modules`、依赖缓存；用户额外排除项保留。

本机凭据、同步连接、锁、缓存、日志、运行中的生命周期状态、临时文件、冲突原件和恢复前备份不随主数据上传。设置中的本机密钥、代理和路径按字段保留。

DSH 0.2.1-rc.3 的当前设置主要在 `profiles/<环境>/cordis.patch.yml`，数据目录下的 `cordis.patch.yml` 是更高优先级的全局覆盖。两处均按字段同步主题、字体字号、模型、搜索及插件偏好；自动同步开关等普通偏好不再整组排除。`dsh-sync.json` 仅投影普通偏好，仓库连接、代理和项目路径配置保留本机原值。

密钥、代理和原有本机路径字段沿用既有规则；`apiKeyEnv` 等环境变量引用名可以同步，实际密钥需在每台电脑配置。本版没有新增按设备、命令或目录字段名称进行整组排除，也没有修改历史会话恢复的工作目录。

合法 `!!js` 动态表达式以带标签的原文传递，插件不执行表达式；支持无循环的 YAML 锚点。Cordis 配置列表只在全部为互不相同的条目补丁时按条目合并；含插入项或重复条目时有执行顺序，冲突时保留完整一侧，另一侧留在恢复记录与 Git 历史，不把配置操作作数组并集。损坏结构、循环引用或含本机字段但身份不唯一的列表会指出具体文件并保留原件。

迁移原件 `settings.yaml.imported`、Electron、`dsh-runtimes/`、`llm-deepseek/` 都不属于在用的用户数据，不同步，也不会进入导出遍历与隐私扫描。

未发送草稿、浏览器视图选择、窗口大小和登录状态不跨机迁移。已上传到 Git 历史的旧内容不会因新增排除规则自动从历史抹除。

传输前检查未上传历史中的敏感内容与超大文件。

**本机缺少的内容不等于删除。** DSH 没有删除会话的操作，所以某台电脑上找不到的会话（以及项目登记）一律视为丢失：不会从同步仓库删除，下次同步会从远端取回到这台电脑；只有插件的显式删除记录才会把会话从同步中移除。附件、设置、指令与技能一次缺少较多（10 个以上，或 3 个以上且占已同步文件的一半）时，本轮同步暂停并让你选择「确认删除」（其他电脑也会删除）或「从远端取回」（恢复到这台电脑，不删除任何东西）；零星删除照常同步。

新会话和可确认的追加更新按宿主能力应用，运行中不直接替换原件。会话分叉分别保留，远端删除不直接删除本机日志；无法安全应用的内容保持待处理。

## 同步仓库与本机存储

（改动）同步页的「同步的会话」「本地存储与备份」「清理远端不再同步的文件」以及新增的同步仓库占用，合并为「同步仓库与本机存储」。点「检查」后每类一行，显示数量和大小；点行末的「明细」打开窗口，列表在窗口内滚动，按钮始终在底部。

| 行 | 显示 | 窗口里能做什么 |
| --- | --- | --- |
| 同步的会话 | 会话数，其中已归档和 DSH 中看不到的数量 | 按「在 DSH 中可见」「已归档」「在 DSH 中看不到」分组选择，移出同步；所有电脑停止同步这些会话，下次同步时从同步仓库删除，各电脑上的副本留在原处。每个会话显示标题，点「预览」看前几条提问 |
| 同步仓库 | 当前内容与本机已经缓存的 Git 历史 | 查看明细，移出同步、移除旧文件或清除历史版本（见下） |
| 本机存储 | 恢复原件、当前同步副本、旧版遗留分别显示 | 见[本机备份](local-storage.md) |
| 远端旧文件 | 旧版本上传过的本机文件数，以及需要先升级的电脑数 | 见上文；只有所有在用的电脑都已升级，或不再使用的电脑已勾选，才能移除 |

同步仓库的明细按上次同步时的同步副本统计：

- 当前内容、历史版本、目录与提交记录各占多少。大小按本机可见的 Git 对象压缩存储计算。浅副本不含完整远端历史，不能把这里的历史大小当成同步仓库的全部占用。
- 按内容分组的当前文件数和占用、历史占用：正在用的会话、已归档的会话、在 DSH 中看不到的会话（没有登记在任何项目下）、附件、设置、全局指令与技能、不再同步的旧文件、同步记录。会话按同步仓库当前的项目登记归组。
- （新增）已归档和在 DSH 中看不到的会话一行有「移出同步」，打开「同步的会话」并选好这一组；不再同步的旧文件一行有「移除」，打开「远端旧文件」。正在用的会话、附件和设置没有删除按钮。
- （新增）这台电脑同步副本的总占用，以及同步分支已不包含、只被本机引用留住的旧历史（例如早先版本清除历史后留下的本机同步前备份）。有这类占用时出现「回收本机空间…」：逐个列出这些引用，只删除同步仓库中仍能找到的（某个分支的历史包含它）旧备份，再回收空间；同步仓库里找不到、只有这台电脑有的历史，以及不是同步前备份的引用都保留。同步仓库、其他电脑和 DSH 数据不变。上次同步详情中的「本机同步副本（含历史）」包含这部分，所以会比「当前内容」大得多。
- 同步仓库中除同步分支外的项目分支、同步前备份分支和电脑同步回执的数量。新电脑只下载同步分支和仍在用的项目分支。

DSH 中归档的会话仍会同步。删除或改写过的文件留在同步仓库的历史中。新电脑只取当前快照；此后只取两次同步之间安全合并所需的增量。会话日志是压缩文件，每次内容变化都会产生新的 Git 对象，所以会话越长、同步次数越多，历史占用越大。统计不修改同步副本、同步仓库或任何分支；连不上同步仓库时不统计其他分支。

### 清除历史版本

（新增）在同步仓库明细中点「清除历史版本…」，同步分支只保留当前内容，并回收当前本机同步副本中的旧历史。新电脑首次同步原本就只下载当前快照；同步仓库的归档分支继续保留旧历史。

1. 检查其他电脑：和移除远端旧文件一样，仍是旧版本、版本未知或超过 30 天未同步的电脑会被列出，并显示最后同步时间。旧版本会把旧历史重新传回去，所以要先在这些电脑上升级并同步一次；不再使用的电脑可以勾选。这台电脑的同步副本和同步仓库不一致时，要先同步一次。
2. 保留旧历史：原同步分支头保留到同步仓库的 `archive/sync-history/…` 分支，不下载整段旧历史，不生成本机 Git 备份文件。
3. 替换同步分支：同步仓库中的同步分支换成只含当前内容的一次记录。检查之后如果有电脑上传了新改动，这一步会停止，什么都不改。
4. 可选：同时删除同步仓库中的同步前备份分支。不删除的话，它们仍占用同步仓库的空间。

检查将同步分支、备份分支和设备分支合并查询，复用已经缓存且与远端一致的设备回执，最多等待 2 分钟；错误会指出分支查询、登录或本机提交读取等具体阶段。清除后只移除与已归档历史完全匹配的本机备份引用，并回收对象空间；独有分支、已变化的引用仍保留，存在未归档的独有恢复提交时停止清除。备份分支在确认后发生变化时，不删除该分支。回收失败会单独提示，不能视为本机空间已经释放。

其他电脑下次同步时自动改用新的历史：旧的同步副本临时另存并列为旧版本遗留，各电脑上的会话、附件和设置不变。归档分支中的旧历史仍占用同步仓库的空间；这个操作把它移出默认同步分支，不承诺降低同步仓库的总大小。项目分支的历史不在此列。
