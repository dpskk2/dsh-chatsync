另一次 Linux 偶发失败来自 `cli-startup.test.mjs` 用真实等待 10 毫秒断言阶段至少经过 10 毫秒。已改为可控时钟，精确断言 25 毫秒阶段和 5 毫秒失败分支，保留时间线与错误状态检查。矩阵不再因为一个平台失败而取消其余平台，以便独立收集全部结果；任一失败仍阻止发布。桌面检查补充单例预检、单测试与整轮超时，避免无终态的进程被误记为通过。

各次失败的脱敏错误摘要和作业编号见 [action-failures.json](action-failures.json)。历史红色运行保留；修复是否完成以最新冻结源码的完整运行及实际发布作业终态判断。

## 已验证与未验证的区别

- 五类风险均有本版源码复核和自动化回归。官方 0.2.0-rc.2 会话校验器参与六项压力场景及新增语义正负样本；有限 fixture catalog 不作为独立语义判定依据。
- Linux Node、Windows Node、Windows Electron 的完整回归分别记录。Windows Node 默认的 GUI 用例跳过由 Electron 的实际执行补齐；Electron 最终结果必须无失败、取消或跳过。
- 实际 tgz 的 43 个运行文件与源码逐字节核对；解包后通过入口导入和 30 项重点回归。这只能证明隔离候选包检查，不能冒充真实 DSH Desktop 安装验收。
- 部分自动故障（并发保存、取消、中断应用、半帧、异常输出、坏 JSON 等）已执行；全部磁盘满、断电、网络盘、跨版本和长期生命周期组合没有完整覆盖。
- 真实 Windows 11 DSH Desktop 窗口、公开宿主 API 安装/冷启动/恢复全流程、物理双机通过 GitHub 的实网验收没有执行。Electron 内置 Node 回归不是这些项目。
- 未访问 Windows 日常维护目录或安装目录，不宣称本机维护源或日常安装已更新。
- README 两个文件没有本任务修改。用户在任务期间对 README.md 的独立修改已保留；发布采用冻结源码中的版本。

## 发布范围

用户连续要求“落实成0.20.2版本并发布”“继续修改并发布”，并在说明真实 Desktop 窗口和物理双机未验收后，再要求“完成任务并检查action的诸多报错”。本次按该发布范围准备 GitHub Release、完整源码 ZIP、校验值及两个同版本 npm 包。未验证项保持 not-verified；任何真实失败、缺失证据或指纹不一致仍阻断发布。

本版不会复用 0.20.1 的宿主结果作为通过，也不会把一次本地或 CI 同步称作物理双机验收。
