# 0.20.2 源码复核

这是 Codex 对本版改动及相关调用路径的审查记录，不是独立第三方安全认证。版本和实际源码、包指纹以 manifest.json 为准。

## 复核链路

从配置读取、正常启动和退出调度、连接验证、内容范围投影、本地导出、会话检查、隔离 Git 合并、隐私检查、上传、本机应用到完成回执和恢复记录逐层检查。项目分支另检查首次空分支、Git 身份/凭据、取消、中文路径和编辑器并发。

| 风险 | 相关源码与结论 | 对应实测 |
| --- | --- | --- |
| 数据丢失 | `project-sync.js` 把项目 Git 操作移至隔离树，核对导出时与应用前哈希，替换时保留原始 inode 并以排他 link 安装，应用中断先恢复再允许同步。`scope.js` 的会话继续通过公开写入接口或离线互斥保护应用，完成回执拒绝未完成应用。 | R1、R2、R7、项目保留窗口和中断恢复；既有 session-safety、session-transfer、two-device 回归。 |
| 损坏扩散 | `session-transfer.js` 除物理连续性外增加官方词汇、当前格式语义及会话身份检查；本地导出、远端树和离线应用均检查。历史格式使用公开历史 catalog，不虚构 v3→v4 所需子会话证据。`workspace-registry.js` 验证登记结构；`yaml.js` 使用有 MIT 许可的 js-yaml 并限制大小、深度、别名和危险键。 | R3 正负样本、伪造远端快进、官方 7173→7183 六场景、R4 完整设置往返、R5/R6 登记和路径破坏输入。 |
| 隐私 | 设置值在传输前投影，按稳定提供方标识保留本机字段；被删除的提供方不把密钥附给其他项目。主数据、项目和恢复路径检查仍生效。项目旁的恢复目录排除于普通传输；超限文件先阻止快照，暂存撤回使忽略规则可重试。 | R4/C3、备份目录排除、issue6 compatibility 大文件/隐私/忽略/原始错误脱敏、既有隐私测试。 |
| 升级与环境 | 新明确开关保留本机选择，旧配置迁移保持；项目和主仓库凭据策略相同，空身份字段回退；继承代理环境并完整解码 UTF-8；保留旧会话世代原字节和既有远端对象，未知格式停止。 | C1/C2、R9/R10、issue6 workspace 与 compatibility、config-api、session-upgrade；Windows 和 Electron 的终态单独记录。 |
| 恢复 | 每次项目替换有本机恢复记录和同文件系统的原始文件保留；中断应用先恢复缺失路径，已有新路径不覆盖；取消只 abort 隔离树。旧版迁移保留未提交删除；历史超限修复仅把当前相同树重新接到已核对远端上，原有本机提交通过事务性备份 ref 保留，无强推或项目文件改写。主会话分叉、修复、脱敏副本及公开 API 恢复路径保留。 | 项目中断/保留窗口、中文冲突双方原件、session-repair、session-recovery、branch-history 等回归。 |

## 保留的验证边界

原件保留不等于穷尽所有文件系统故障；尚未覆盖全部断电、磁盘满、跨盘/网络盘、不支持硬链接的文件系统、旧文件句柄无限持续写入和所有恶意竞争。不能排他安装或无法保证备份时会报错停止；不能宣称所有 Windows 文件系统均已实测。

实际 DSH Desktop 窗口、公开宿主 API 冷启动/恢复全流程、Windows 11 日常安装、物理双机 GitHub 实网未执行。本版不能沿用 0.20.1 的真实宿主结果作为通过。完整自动回归也不等于这几项原生验收。

## 以前的全面检查为什么仍会遗漏

“运行了很多测试”不代表覆盖了每种运行顺序或有独立正确答案。这里将本次发现对应到原先缺失的检查条件：

| 先前容易通过的检查 | 实际缺口与本版补充 |
| --- | --- |
| 两个静态目录顺序同步成功 | 未在项目合并、替换窗口插入编辑器新保存，也未覆盖首次迁移中尚未提交的删除；补入真实 Git 交错与 inode 保留测试。 |
| 主数据取消和重试 | 没有中断项目冲突并检查 MERGE_HEAD、冲突标记与下一轮推送；补入项目取消故障。 |
| 只验证序号连续或使用有限的 fixture catalog | 不能证明宿主事件生命周期合法；加入官方校验器的正样本、语义错误负样本、远端快进拦截和离线检查。 |
| 使用同一 YAML 解析器做写出再读回 | 无法发现它把注释或字符串错误解释；改用明确的期望值和完整双副本往返，并更换可靠解析器。 |
| 正常登记与路径文件 | catch 后的空对象/空列表掩盖损坏；增加坏 JSON、坏结构和 BOM 输入，并断言没有远端提交。 |
| 同步 API 返回成功 | 镜像更新不等于本机完成应用；检查退出上传后的实际文件与回执。 |
| 英文短路径、ASCII 输出 | 未覆盖 Git 引号路径、NUL 分隔、UTF-8 跨 chunk；加入中文/空格冲突和拆字节输出。 |
| 测试机已有 Git 身份与凭据 | 会掩盖新机器缺少全局配置；新增隔离空配置、仓库身份回退及凭据策略一致性检查。真实 GitHub 登录状态仍属未验证。 |
| 当前文件已经删除 | Git 历史仍含旧超限对象；新增旧历史扫描、预览绑定、并发变化拒绝、保留完整备份并重接相同树的检查。 |
| PowerShell 直接调用 GUI 可执行文件 | 可能在测试进程结束前返回，使“启动了测试”看起来像“通过了测试”；现在由 Node 进程 API 等待 Electron 真实退出，检查实际运行时与退出码，同时执行 GUI 等待用例。 |

上述补充减少已知缺口，不是对未来所有输入、交错和平台的无缺陷保证。


补充检查发现：插件安装位置与宿主依赖分离时，退出/停机同步子进程会失去宿主公开格式模块的解析位置。本版由父宿主明确传递自己的入口路径，关闭后同步和修复工作进程同样继承；只解析公开包导出，不扫描宿主私有实现，也不降低语义校验。新增隔离安装场景分别断言：没有入口时拒绝并保留原件，有已知入口时由真实退出工作进程校验会话并生成逐字节一致的 Git 快照。
